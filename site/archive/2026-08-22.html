오늘의 SQLD 문제 (40문제)

정답률 확인 중...

  1. [SQL 기본 및 활용]

    다음 SQL 'SELECT PROD_ID FROM SALES_2025 UNION SELECT PROD_ID FROM SALES_2026'의 결과에 대한 설명으로 가장 옳은 것은?

    UNION은 합집합 연산이므로 두 SELECT 결과를 합쳐 중복을 제거한 값을 반환한다. 즉, 2025년 또는 2026년 중 하나라도 판매 이력이 있는 상품 ID가 중복 없이 나열된다. 모두 판매된 것만 원한다면 INTERSECT를 사용해야 한다.

  2. [SQL 기본 및 활용]

    다음 SQL 'SELECT CUST_ID FROM VIP_CUST INTERSECT SELECT CUST_ID FROM COMPLAIN_CUST'의 결과에 대한 설명으로 가장 옳은 것은?

    INTERSECT는 두 결과 집합의 교집합을 반환하므로, VIP_CUST와 COMPLAIN_CUST 양쪽 모두에 존재하는 CUST_ID, 즉 VIP이면서 동시에 불만 이력이 있는 고객만 반환한다.

  3. [SQL 기본 및 활용]

    다음 SQL 'SELECT CUST_ID FROM ALL_CUST MINUS SELECT CUST_ID FROM WITHDRAWN_CUST'의 결과에 대한 설명으로 가장 옳은 것은?

    MINUS는 차집합이므로 ALL_CUST에서 WITHDRAWN_CUST에 존재하는 행을 제외한 나머지, 즉 탈퇴 이력이 없는 고객만 남긴다.

  4. [SQL 기본 및 활용]

    집합 연산자로 결합되는 각 SELECT문의 컬럼 대응 기준에 대한 설명으로 가장 옳은 것은?

    집합 연산자는 컬럼명이 아니라 SELECT 절에 나열된 순서(위치)로 각 컬럼을 대응시킨다. 따라서 컬럼명이 달라도 개수와 자료형(호환성)만 맞으면 결합할 수 있으며, 결과의 컬럼명은 첫 번째 SELECT문을 따른다.

  5. [SQL 기본 및 활용]

    동일한 두 결과 집합에 대해 UNION을 적용한 결과와 UNION ALL을 적용한 결과의 행 수를 비교한 설명으로 가장 옳은 것은? (단, 두 결과 집합에 중복되는 행이 존재한다고 가정한다)

    UNION ALL은 중복을 제거하지 않고 단순히 결과를 모두 이어붙이므로, 중복되는 행이 하나라도 있으면 UNION(중복 제거)의 결과보다 행 수가 많거나 같다. 중복이 전혀 없다면 두 결과의 행 수는 같다.

  6. [SQL 기본 및 활용]

    MINUS 연산의 교환법칙 성립 여부에 대한 설명으로 가장 옳은 것은?

    MINUS(차집합)는 연산 순서에 따라 기준이 되는 집합이 달라지므로 교환법칙이 성립하지 않는다. 따라서 A와 B의 내용이 다르면 A MINUS B와 B MINUS A는 서로 다른 결과를 낸다.

  7. [SQL 기본 및 활용]

    결합하려는 두 SELECT문의 컬럼 개수가 서로 다를 때 집합 연산자를 사용하면 어떻게 되는가?

    집합 연산자를 사용하려면 결합되는 모든 SELECT문의 컬럼 개수가 동일해야 하며, 개수가 다르면 SQL 오류가 발생한다. 자동으로 NULL이 채워지지 않는다.

  8. [SQL 기본 및 활용]

    본사 직원 테이블과 지사 직원 테이블처럼 구조는 같지만 물리적으로 분리된 두 테이블의 데이터를 하나의 결과로 합쳐서 조회하고자 할 때 가장 적절한 방법은?

    본사/지사처럼 물리적으로 분리되어 있지만 구조가 동일한 테이블의 데이터를 세로로 합쳐 하나의 목록처럼 다루는 것은 집합 연산자(UNION/UNION ALL)의 전형적인 활용 사례이다. 옆으로 붙이는 것은 조인, 소계는 그룹 함수, 트리 구조는 계층형 질의가 적합하다.

  9. [SQL 기본 및 활용]

    집합 연산자로 결합된 여러 SELECT문에서 WHERE 조건 사용에 대한 설명으로 가장 옳은 것은?

    집합 연산자로 결합되는 각 SELECT문은 독립적인 쿼리이므로 서로 다른 WHERE 조건을 각각 자유롭게 지정할 수 있다. 다만 SELECT 절의 컬럼 개수/자료형은 맞춰야 한다.

  10. [SQL 기본 및 활용]

    집합 연산자(UNION, INTERSECT, MINUS 등)가 중복 여부나 교집합/차집합 여부를 판단하는 기준에 대한 설명으로 가장 옳은 것은?

    UNION, INTERSECT, MINUS 등의 집합 연산은 결과 집합의 각 행(모든 컬럼 값의 조합)을 기준으로 비교하여 중복·교집합·차집합 여부를 판단한다.

  11. [SQL 기본 및 활용]

    결과 집합 A, B에 대해 (A UNION B) MINUS (A INTERSECT B)의 의미로 가장 옳은 것은?

    A UNION B는 합집합, A INTERSECT B는 교집합이므로 합집합에서 교집합을 뺀 결과는 A와 B 중 정확히 한쪽에만 존재하는 행들(대칭차집합)만 남는다.

  12. [SQL 기본 및 활용]

    서로 다른 조건을 만족하는 두 부서 목록을 조회한 뒤, 두 목록에서 중복되는 부서를 한 번씩만 보고 싶을 때 사용해야 할 집합 연산자로 가장 적절한 것은?

    두 결과에 중복된 행이 존재할 수 있고 이를 한 번씩만 보고 싶다면 중복을 제거해 주는 UNION을 사용해야 한다. UNION ALL은 중복을 그대로 남기므로 목적에 맞지 않는다.

  13. [SQL 기본 및 활용]

    'INSERT INTO EMP(EMP_ID, EMP_NAME) VALUES (101, '홍길동')'처럼 컬럼 목록을 명시한 INSERT문에서, 나열하지 않은 나머지 컬럼에는 어떤 값이 들어가는가?

    INSERT문에서 컬럼 목록을 명시하면 VALUES의 값 개수는 나열한 컬럼 개수와 일치하면 되고, 나열하지 않은 컬럼에는 DEFAULT 값(정의되어 있다면) 또는 NULL이 들어간다(단, NOT NULL이면서 DEFAULT가 없는 컬럼은 값을 반드시 지정해야 한다).

  14. [SQL 기본 및 활용]

    UPDATE문에서 WHERE 절을 생략했을 때의 동작에 대한 설명으로 가장 옳은 것은?

    UPDATE문의 WHERE 절은 수정 대상 행을 제한하는 역할을 하며, 이를 생략하면 테이블의 모든 행이 SET 절에 지정된 대로 수정된다. 실무에서 의도치 않은 전체 수정 사고의 대표적 원인이다.

  15. [SQL 기본 및 활용]

    다음 SQL 'DELETE FROM EMP WHERE DEPT_ID = 10'의 실행 결과에 대한 설명으로 가장 옳은 것은?

    DELETE는 WHERE 조건에 해당하는 행만 삭제하는 DML 명령으로, 테이블 자체(구조)는 그대로 유지된다. 조건에 맞는 행, 즉 DEPT_ID가 10인 행만 제거된다.

  16. [SQL 기본 및 활용]

    MERGE문의 기능에 대한 설명으로 가장 옳은 것은?

    MERGE(UPSERT)는 소스와 대상을 조인 조건으로 비교하여, 일치하는 행이 있으면 WHEN MATCHED 절(주로 UPDATE, 경우에 따라 DELETE)을, 없으면 WHEN NOT MATCHED 절(INSERT)을 수행하는 DML 명령이다.

  17. [SQL 기본 및 활용]

    MERGE문에서 WHEN MATCHED THEN UPDATE 절이 적용되는 대상에 대한 설명으로 가장 옳은 것은?

    MERGE문의 WHEN MATCHED 절은 조인(매칭) 조건을 만족하는, 즉 소스와 대상 양쪽에 대응하는 행이 이미 존재하는 경우에 대해 UPDATE(또는 DELETE) 동작을 수행한다.

  18. [SQL 기본 및 활용]

    INSERT INTO 문에서 컬럼 목록 없이 VALUES 절만으로 값을 나열할 때 지켜야 할 사항으로 가장 옳은 것은?

    INSERT ... VALUES 구문에서는 (명시했든 생략했든) 컬럼의 순서에 맞춰 값을 나열해야 하며, 개수와 순서가 어긋나면 오류가 발생하거나 의도하지 않은 컬럼에 값이 들어간다.

  19. [SQL 기본 및 활용]

    다음 SQL 'UPDATE EMP SET SALARY = SALARY * 1.1 WHERE DEPT_ID = 20'의 실행 결과에 대한 설명으로 가장 옳은 것은?

    SET 절의 SALARY = SALARY * 1.1은 각 행마다 자기 자신의 기존 SALARY 값을 기준으로 1.1배 계산하여 대입하는 것이며, WHERE 절에 의해 DEPT_ID가 20인 행으로 대상이 한정된다.

  20. [SQL 기본 및 활용]

    다음 SQL 'INSERT INTO SUMMARY_TBL SELECT DEPT_ID, COUNT(*) FROM EMP GROUP BY DEPT_ID'에 대한 설명으로 가장 옳은 것은?

    INSERT INTO ... SELECT 형태는 VALUES 절 없이 SELECT문의 조회 결과를 그대로 대상 테이블에 삽입하는 방식이며, GROUP BY 등 일반 SELECT문에서 쓸 수 있는 절을 함께 사용할 수 있다.

  21. [SQL 기본 및 활용]

    MERGE문에서 ON 절 조건에 일치하지 않는 소스 행에 대한 처리로 가장 옳은 것은? (WHEN NOT MATCHED THEN INSERT 절이 정의되어 있다고 가정)

    MERGE문에서 ON 절 조건으로 대상 테이블과 매칭되지 않는 소스 행은 WHEN NOT MATCHED THEN INSERT 절이 정의되어 있다면 새 행으로 삽입된다.

  22. [SQL 기본 및 활용]

    TRUNCATE와 DELETE의 조건부 삭제 지원 여부에 대한 설명으로 가장 옳은 것은?

    TRUNCATE는 테이블의 모든 행을 한 번에 제거하는 명령으로 WHERE 절을 사용한 조건부 삭제를 지원하지 않는다. 반면 DELETE는 WHERE 절로 삭제 대상 행을 선택적으로 지정할 수 있다.

  23. [SQL 기본 및 활용]

    다른 테이블의 여러 행(또는 조회 결과)을 하나의 SQL로 대상 테이블에 한 번에 삽입하고자 할 때 가장 적절한 방법은?

    INSERT INTO ... SELECT는 SELECT문이 반환하는 여러 행을 한 번의 INSERT 실행으로 모두 삽입할 수 있어, 대량의 데이터를 옮기거나 요약 테이블을 채울 때 유용하다. 컬럼명이 아니라 컬럼의 개수와 순서(자료형 호환)가 기준이 된다.

  24. [SQL 기본 및 활용]

    UPDATE문의 SET 절에 여러 컬럼을 콤마로 나열했을 때의 동작으로 가장 옳은 것은?

    UPDATE ... SET 절에는 콤마로 구분하여 여러 컬럼과 그 값을 나열할 수 있으며, WHERE 조건을 만족하는 각 행에 대해 나열된 컬럼들이 모두 동시에 갱신된다.

  25. [SQL 기본 및 활용]

    외래 키 제약으로 자식 테이블이 참조 중인 부모 테이블의 행을 DELETE하려고 할 때의 결과로 가장 옳은 것은? (별도의 삭제 연쇄 옵션이 없다고 가정)

    외래 키 제약이 걸려 있고 별도의 삭제 연쇄(CASCADE 등) 옵션이 없다면, 자식 테이블에서 참조 중인 부모 행을 삭제하려는 DELETE는 참조 무결성 위반으로 실패할 수 있다.

  26. [SQL 기본 및 활용]

    NOT NULL 제약이 걸린 컬럼에 값을 지정하지 않고 INSERT를 수행하면 어떻게 되는가? (DEFAULT 값도 없다고 가정)

    NOT NULL 제약은 해당 컬럼이 NULL 값을 가질 수 없도록 강제하므로, INSERT 시 값을 지정하지 않고 DEFAULT도 정의되어 있지 않다면 제약 위반으로 삽입이 실패한다.

  27. [SQL 기본 및 활용]

    대상 테이블에 데이터가 이미 있는지 애플리케이션에서 먼저 SELECT로 확인한 뒤 INSERT 또는 UPDATE를 분기 실행하던 절차를 SQL 한 문장으로 단순화하고자 할 때 가장 적합한 것은?

    MERGE는 조인 조건에 따라 데이터의 존재 여부를 SQL 엔진이 판단하여 INSERT(WHEN NOT MATCHED)와 UPDATE/DELETE(WHEN MATCHED)를 한 번에 처리하므로, 존재 여부를 미리 조회해 분기 처리하는 절차형 로직을 단순화할 수 있다.

  28. [SQL 기본 및 활용]

    UPDATE문의 SET 절에 서브쿼리를 사용하는 것에 대한 설명으로 가장 옳은 것은?

    UPDATE ... SET 컬럼 = (서브쿼리) 형태로, 다른 테이블을 참조해 조회한 값을 갱신 값으로 사용할 수 있다. 이때 서브쿼리는 일반적으로 단일 행(하나의 값)을 반환해야 한다.

  29. [SQL 기본 및 활용]

    조건을 만족하는 행이 하나도 없는 상태에서 'DELETE FROM TBL WHERE 조건'을 실행하면 어떤 일이 벌어지는가?

    DELETE문은 WHERE 조건을 만족하는 행이 없더라도 오류 없이 정상 처리되며, 이 경우 삭제된 행의 수는 0건이 된다.

  30. [SQL 기본 및 활용]

    테이블 A의 값을 기준으로 테이블 B의 값을 최신 상태로 동기화(있으면 갱신, 없으면 새로 추가)하는 배치 작업을 구현할 때 가장 적절한 방법은?

    MERGE는 소스와 대상을 조인 조건으로 비교해 존재 여부에 따라 UPDATE/INSERT를 한 번에 처리할 수 있어, 두 테이블 간 데이터를 동기화하는 배치 로직을 간결하게 구현할 수 있다.

  31. [SQL 기본 및 활용]

    다음 SQL 'UPDATE EMP SET DEPT_ID = NULL WHERE EMP_ID = 500'에 대한 설명으로 가장 옳은 것은? (DEPT_ID 컬럼에 NOT NULL 제약이 없다고 가정)

    SET 컬럼 = NULL은 해당 컬럼 값을 실제 NULL(값 없음)로 설정하는 것이며, DEPT_ID에 NOT NULL 제약이 없다면 정상적으로 처리되어 WHERE 조건에 해당하는 행만 변경된다.

  32. [SQL 기본 및 활용]

    MERGE문에서 WHEN MATCHED 절과 WHEN NOT MATCHED 절의 작성 방식에 대한 설명으로 가장 옳은 것은?

    MERGE문은 WHEN MATCHED와 WHEN NOT MATCHED 절을 함께 사용해 갱신과 삽입을 한 번에 처리할 수 있고, 필요에 따라 둘 중 한 절만 사용할 수도 있다.

  33. [SQL 기본 및 활용]

    INSERT, UPDATE, DELETE, MERGE의 SQL 명령어 분류에 대한 설명으로 가장 옳은 것은?

    SQL 명령어 분류상 INSERT, UPDATE, DELETE, MERGE는 데이터 자체를 삽입/수정/삭제/병합하는 DML에 해당하며, 테이블 구조를 정의/변경하는 CREATE, ALTER, DROP 등은 DDL로 분류된다.

  34. [SQL 기본 및 활용]

    COMMIT하지 않은 상태에서 DML(INSERT/UPDATE/DELETE)로 변경한 내용을 ROLLBACK했을 때의 동작으로 가장 옳은 것은?

    일반적으로 DML(INSERT/UPDATE/DELETE 등)로 변경한 내용은 COMMIT 이전까지는 확정되지 않은 상태이며, 같은 트랜잭션 내에서 ROLLBACK을 실행하면 해당 변경을 취소하고 이전 상태로 되돌릴 수 있다.

  35. [SQL 기본 및 활용]

    테이블 B의 각 행이 테이블 A와 키 값으로 매칭되는지에 따라 서로 다른 처리를 하고 싶을 때, 여러 개의 개별 UPDATE/INSERT문을 작성하는 대신 사용할 수 있는 방법으로 가장 적절한 것은?

    MERGE문은 ON 절의 매칭 조건 결과(WHEN MATCHED / WHEN NOT MATCHED)에 따라 서로 다른 DML 동작을 하나의 문장 안에서 지정할 수 있어, 조건부 갱신/삽입 로직을 간결하게 표현할 수 있다.

  36. [SQL 기본 및 활용]

    다음 SQL "DELETE FROM ORDERS WHERE ORDER_DATE < DATE '2020-01-01'"을 실행한 직후, 별도로 COMMIT을 하지 않은 상태에 대한 설명으로 가장 옳은 것은?

    트랜잭션 처리 방식에 따라, COMMIT 이전의 DML 변경 사항은 해당 트랜잭션(세션) 내에서는 보이지만 COMMIT 전까지는 다른 세션에는 반영되지 않을 수 있다. 이는 일관성 있는 트랜잭션 격리를 위한 기본 동작이다.

  37. [SQL 기본 및 활용]

    PRIMARY KEY 제약이 설정된 컬럼(또는 컬럼 조합)의 특성에 대한 설명으로 가장 옳은 것은?

    PRIMARY KEY 제약은 NOT NULL과 UNIQUE 제약의 특성을 모두 가지므로, 해당 컬럼(또는 컬럼 조합)은 NULL을 가질 수 없고 테이블 내에서 값이 유일해야 한다.

  38. [SQL 기본 및 활용]

    FOREIGN KEY 제약의 역할에 대한 설명으로 가장 옳은 것은?

    FOREIGN KEY(외래 키)는 참조하는 테이블의 특정 컬럼에 실제로 존재하는 값만 허용함으로써, 두 테이블 간의 데이터 일관성(참조 무결성)을 보장하는 제약 조건이다.

  39. [SQL 기본 및 활용]

    CHECK 제약의 역할에 대한 설명으로 가장 옳은 것은?

    CHECK 제약은 사용자가 지정한 논리식(조건)을 만족하는 값만 저장되도록 강제하는 제약 조건으로, 예를 들어 급여가 0보다 커야 한다거나 상태 값이 특정 목록 중 하나여야 한다는 규칙을 표현할 때 사용한다.

  40. [SQL 기본 및 활용]

    UNIQUE 제약과 PRIMARY KEY 제약의 차이에 대한 설명으로 가장 옳은 것은?

    UNIQUE 제약은 컬럼 값의 유일성만을 강제하며, 대부분의 DBMS에서 NULL 값은 유일성 비교에서 제외되어 여러 행이 NULL을 가질 수 있다. 이 점이 NOT NULL까지 포함하는 PRIMARY KEY와의 차이다.
