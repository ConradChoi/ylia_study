오늘의 SQLD 문제 (40문제)

정답률 확인 중...

  1. [데이터 모델링의 이해]

    서브타입마다 슈퍼타입 속성까지 합쳐 개별 테이블로 만드는 변환 방식의 특징으로 옳은 것은?

    서브타입 테이블에 슈퍼타입 속성까지 모두 포함시켜 개별 테이블로 만드는 방식은 조인 없이 서브타입별 전체 데이터를 바로 조회할 수 있지만, 슈퍼타입의 공통 속성이 여러 서브타입 테이블에 중복되어 저장된다는 특징이 있다.

  2. [데이터 모델링의 이해]

    트랜잭션의 특성(ACID) 중 '원자성(Atomicity)'에 대한 설명으로 가장 적절한 것은?

    원자성은 트랜잭션에 포함된 연산들이 전부(All) 성공적으로 반영되거나, 하나라도 실패하면 전혀(Nothing) 반영되지 않아야 한다는 특성이다.

  3. [데이터 모델링의 이해]

    트랜잭션의 특성(ACID) 중 '일관성(Consistency)'에 대한 설명으로 가장 적절한 것은?

    일관성은 트랜잭션 실행 전과 후에 데이터베이스가 정해진 제약조건이나 규칙을 만족하는 일관된 상태를 유지해야 한다는 특성이다.

  4. [데이터 모델링의 이해]

    트랜잭션의 특성(ACID) 중 '고립성(Isolation)'에 대한 설명으로 가장 적절한 것은?

    고립성(격리성)은 여러 트랜잭션이 동시에 실행되더라도 각 트랜잭션이 다른 트랜잭션의 중간 연산 결과를 참조하지 못하도록 격리되어야 한다는 특성이다.

  5. [데이터 모델링의 이해]

    트랜잭션의 특성(ACID) 중 '지속성(Durability)'에 대한 설명으로 가장 적절한 것은?

    지속성은 트랜잭션이 성공적으로 커밋되면 그 결과가 시스템 장애(전원 차단, 크래시 등)가 발생하더라도 영구적으로 유지되어야 한다는 특성이다.

  6. [데이터 모델링의 이해]

    인덱스(Index)에 대한 설명으로 가장 적절한 것은?

    인덱스는 특정 컬럼 값을 빠르게 찾을 수 있도록 별도로 구성한 자료구조(대표적으로 B-Tree)로, 조회 성능 향상을 목적으로 생성한다.

  7. [데이터 모델링의 이해]

    인덱스를 생성했을 때 일반적으로 나타나는 트레이드오프로 가장 적절한 것은?

    인덱스는 조회 성능을 높이는 대신, 데이터 변경(INSERT/UPDATE/DELETE) 시 인덱스 구조도 함께 갱신해야 하므로 추가적인 저장 공간과 처리 부하가 발생한다.

  8. [데이터 모델링의 이해]

    일반적으로 인덱스를 생성하기에 적합한 컬럼의 특성으로 가장 거리가 먼 것은?

    성별처럼 값의 종류가 2~3개에 불과해 카디널리티(선택도)가 매우 낮은 컬럼은 인덱스를 걸어도 검색 범위를 크게 좁히지 못해 인덱스 효과가 떨어진다.

  9. [데이터 모델링의 이해]

    일반적으로 데이터베이스가 테이블을 생성할 때 기본키(Primary Key)에 대해 자동으로 생성해 주는 것은?

    대부분의 관계형 데이터베이스는 기본키 제약조건을 설정하면 유일성을 보장하기 위해 자동으로 고유(Unique) 인덱스를 함께 생성한다.

  10. [데이터 모델링의 이해]

    데이터 모델링에서 '개념적 데이터 모델링' 단계에 대한 설명으로 가장 적절한 것은?

    개념적 데이터 모델링은 특정 DBMS에 종속되지 않고 업무의 핵심 엔터티, 속성, 관계를 추상적으로 정의하는 단계로, 이후 논리/물리 모델링의 기초가 된다.

  11. [데이터 모델링의 이해]

    '논리적 데이터 모델링'과 '물리적 데이터 모델링'의 차이에 대한 설명으로 가장 적절한 것은?

    논리 모델링은 특정 DBMS 제품에 독립적으로 업무 규칙과 정규화를 반영한 상세 모델을 만드는 단계이며, 물리 모델링은 이를 특정 DBMS의 테이블, 컬럼, 자료형, 인덱스 등으로 구체화하는 단계이다.

  12. [데이터 모델링의 이해]

    데이터 모델링에서 '무결성 제약조건(Integrity Constraint)'에 대한 설명으로 가장 적절한 것은?

    무결성 제약조건은 개체 무결성, 참조 무결성, 도메인 무결성 등과 같이 데이터의 정확성과 일관성을 유지하기 위해 데이터베이스에 부여하는 규칙이다.

  13. [데이터 모델링의 이해]

    참조 무결성(Referential Integrity)에 대한 설명으로 가장 적절한 것은?

    참조 무결성은 외래키가 참조하는 부모 테이블의 기본키(또는 후보키) 값 중 하나이거나 NULL이어야 한다는 제약으로, 서로 다른 테이블 간 데이터의 일관성을 보장한다.

  14. [데이터 모델링의 이해]

    개체 무결성(Entity Integrity)에 대한 설명으로 가장 적절한 것은?

    개체 무결성은 기본키를 구성하는 모든 컬럼이 NULL 값을 가질 수 없으며 유일한 값을 가져야 한다는 제약으로, 각 인스턴스의 유일한 식별을 보장한다.

  15. [데이터 모델링의 이해]

    속성 중 그 값이 업무 규칙에 따라 코드화되어 관리되는 값(예: 상태코드 'A'=신청, 'C'=완료)을 관리하는 별도의 테이블을 일반적으로 무엇이라 하는가?

    코드값과 그 의미를 별도로 관리하는 테이블을 공통코드(코드) 테이블이라고 하며, 여러 엔터티에서 공통으로 참조하여 코드의 일관성을 유지하는 데 사용한다.

  16. [데이터 모델링의 이해]

    데이터 값의 변경 이력을 시간의 흐름에 따라 관리하기 위해 별도로 두는 엔터티(또는 컬럼 구조)를 일반적으로 무엇이라 하는가?

    이력 엔터티(이력 테이블)는 데이터가 시간에 따라 변경되는 값을 이전 값과 함께 관리하기 위해 별도로 설계하는 엔터티로, 반정규화 상황이나 감사(Audit) 목적으로 자주 사용된다.

  17. [데이터 모델링의 이해]

    엔터티의 명명 규칙으로 일반적으로 권장되지 않는 것은?

    '데이터', '정보'와 같이 여러 대상을 모호하게 지칭할 수 있는 포괄적인 이름은 엔터티 명명 시 지양해야 하며, 그 업무를 명확히 나타내는 구체적인 이름을 사용하는 것이 바람직하다.

  18. [데이터 모델링의 이해]

    속성 명명 규칙으로 가장 적절하지 않은 것은?

    속성명이 전체 모델에서 반드시 유일해야 한다는 규칙은 없으며, 오히려 같은 의미를 갖는 속성이라면 여러 엔터티에서 동일한 이름을 일관되게 사용하는 것이 바람직하다.

  19. [데이터 모델링의 이해]

    '도메인(Domain)'에 대한 데이터 모델링 관점의 설명으로 가장 적절한 것은?

    도메인은 하나의 속성이 취할 수 있는 값의 범위(자료형, 길이, 제약조건 등)를 의미하며, 동일한 도메인을 공유하는 속성들은 일관된 값의 범위와 형식을 갖는다.

  20. [데이터 모델링의 이해]

    다음 중 엔터티로 도출하는 것이 가장 타당한 경우는?

    '주문'처럼 여러 속성을 가지고 고유하게 식별되어야 하며 반복적으로 인스턴스가 발생하는 업무 대상은 엔터티로 도출하는 것이 타당하다. 나머지는 특정 엔터티에 속하는 단순/파생 속성의 성격에 가깝다.

  21. [데이터 모델링의 이해]

    다음 중 '주식별자의 대체 여부'에 따라 식별자를 분류할 때, 주식별자와 보조식별자의 관계를 가장 바르게 설명한 것은?

    보조식별자(대체키)는 유일성을 만족하지만 주식별자로 채택되지 않은 속성으로, 주로 조회나 대체 조건으로 활용되며 모든 엔터티가 반드시 가져야 하는 것은 아니다.

  22. [데이터 모델링의 이해]

    다음 중 함수적 종속성(Functional Dependency) 표기 'A → B'의 의미로 가장 적절한 것은?

    A → B는 'A가 B를 함수적으로 결정한다'는 의미로, A의 값이 정해지면 그에 대응하는 B의 값이 하나로 유일하게 결정됨을 나타낸다. 이때 A를 결정자, B를 종속자라고 한다.

  23. [데이터 모델링의 이해]

    관계형 데이터 모델에서 '후보키(Candidate Key)'에 대한 설명으로 가장 적절한 것은?

    후보키는 유일성과 최소성을 만족하여 기본키(주식별자) 후보가 될 수 있는 속성 또는 속성 집합이며, 이 중 하나가 선정되어 주식별자가 되고 나머지는 보조식별자(대체키)가 된다.

  24. [데이터 모델링의 이해]

    엔터티 내 특정 속성이 다른 엔터티의 주식별자를 참조하기 위해 포함하는 속성을 무엇이라 하는가?

    외래키는 다른 엔터티(테이블)의 주식별자(기본키)를 참조하기 위해 포함하는 속성으로, 두 엔터티 간의 관계를 관계형 데이터베이스에서 실제로 구현하는 수단이다.

  25. [SQL 기본 및 활용]

    SQL에서 테이블의 모든 컬럼을 조회할 때 사용하는 기호는 무엇인가?

    테이블의 모든 컬럼을 조회하려면 SELECT 절에 애스터리스크(*)를 사용한다. ALL, FULL, ANY는 각각 다른 용도로 쓰이는 키워드로 전체 컬럼 조회 기호가 아니다.

  26. [SQL 기본 및 활용]

    SELECT 문에서 중복된 행을 제거하고 유일한 값만 조회하기 위해 사용하는 키워드는?

    DISTINCT 키워드는 SELECT 절에서 중복된 행을 제거하고 유일한 결과만 반환한다. UNIQUE ONLY, SINGLE, NODUP은 SQL 표준 키워드가 아니다.

  27. [SQL 기본 및 활용]

    다음 중 컬럼에 별칭(Alias)을 부여하는 문법으로 올바르지 않은 것은?

    컬럼 별칭은 AS 키워드를 사용하거나 AS를 생략하고 공백으로 구분하여 부여할 수 있으며, 별칭에 공백이나 특수문자가 포함될 경우 큰따옴표로 감쌀 수 있다. '#' 기호는 별칭 지정 문법에 사용되지 않는다.

  28. [SQL 기본 및 활용]

    SELECT 절에서 문자열을 다른 문자열이나 컬럼 값과 연결(concatenation)할 때 표준 SQL에서 사용하는 연산자는?

    표준 SQL에서 문자열 연결 연산자는 이중 파이프(||)이다. 일부 DBMS(예: SQL Server)는 +를 사용하기도 하지만 ANSI 표준 연산자는 ||이다.

  29. [SQL 기본 및 활용]

    NULL 값에 대한 설명으로 가장 옳은 것은?

    NULL은 '값이 없음' 또는 '알 수 없음'을 나타내는 특수한 상태로, 0이나 빈 문자열과 다르며 NULL이 포함된 산술 연산의 결과는 NULL이 된다. 정렬 시 NULL의 처리 순서는 DBMS마다 다르게 정의된다.

  30. [SQL 기본 및 활용]

    다음 중 SQL 문의 실행 순서를 논리적으로 나열할 때, SELECT 절이 실제로 처리되는 시점으로 옳은 것은?

    SQL의 논리적 처리 순서는 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY 순이다. SELECT 절은 집계와 필터링이 끝난 뒤, 정렬 이전에 처리된다.

  31. [SQL 기본 및 활용]

    숫자 컬럼 SALARY에 대해 10% 인상된 값을 조회하고자 할 때 올바른 SELECT 절은?

    SALARY 값을 10% 인상하려면 원래 값에 1.1을 곱하면 된다. %, #, UP은 산술 연산자로 사용되지 않는다.

  32. [SQL 기본 및 활용]

    SQL 주석(comment) 처리 방법으로 옳지 않은 것은?

    표준 SQL에서 한 줄 주석은 '--', 여러 줄 주석은 '/* ... */'로 표현한다. '%% ... %%' 형태는 SQL 주석 문법이 아니다.

  33. [SQL 기본 및 활용]

    테이블 없이 상수 값만 조회하는 SQL 문의 예로 가장 적절한 것은? (Oracle 기준 DUAL 테이블 사용)

    Oracle에서는 FROM 절이 필수이므로 테이블 없이 상수만 조회할 때 더미 테이블인 DUAL을 사용한다. 'SELECT 1+1 AS 결과;'처럼 FROM 절을 생략하면 Oracle 문법 오류가 발생한다.

  34. [SQL 기본 및 활용]

    다음 중 SELECT 문의 기본 구조에서 반드시 포함되어야 하는 절은?

    SELECT 문에서 조회할 컬럼을 지정하는 SELECT 절과 대상 테이블을 지정하는 FROM 절은 기본적으로 필수 구성 요소이다(단, DUAL 같은 더미 테이블을 쓰는 특수한 경우 제외). WHERE, ORDER BY, GROUP BY는 선택 사항이다.

  35. [SQL 기본 및 활용]

    다음 중 컬럼 값을 조건에 따라 다른 값으로 치환하여 조회할 때 사용할 수 있는 함수로 가장 적절한 것은?

    CASE WHEN 구문은 조건에 따라 값을 다르게 반환하는 표준 SQL 표현식이다. CONVERT WHEN, SWITCH WHEN, IF THEN GOTO는 표준 SQL 문법이 아니다.

  36. [SQL 기본 및 활용]

    NULL 값을 다른 값으로 대체하여 조회하고 싶을 때 사용하는 함수로 옳지 않은 것은? (여러 DBMS 공통 함수 포함)

    NVL(Oracle), COALESCE(표준 SQL), ISNULL(SQL Server)은 모두 NULL 값을 대체하는 함수이다. REPLACE는 문자열 내 특정 부분 문자열을 치환하는 함수로 NULL 대체 용도가 아니다.

  37. [SQL 기본 및 활용]

    SELECT 절에 작성한 표현식의 결과에 별칭을 지정하지 않았을 때 일반적으로 나타나는 컬럼 헤더로 옳은 것은?

    별칭을 지정하지 않으면 대부분의 DBMS는 SELECT 절에 작성된 표현식(함수식, 연산식 등) 자체를 컬럼 헤더로 표시한다. 이는 가독성이 떨어지므로 보통 별칭을 부여하는 것이 권장된다.

  38. [SQL 기본 및 활용]

    다음 중 오늘 날짜(현재 날짜)를 조회하는 표준적인 함수로 가장 널리 쓰이는 것은?

    표준 SQL에서 현재 날짜를 반환하는 함수는 CURRENT_DATE이며, DBMS에 따라 SYSDATE(Oracle), GETDATE()(SQL Server) 등의 변형이 존재한다. TODAY(), NOW_DATE, GET_DATE_TODAY()는 표준 함수명이 아니다.

  39. [SQL 기본 및 활용]

    문자열의 길이를 반환하는 표준 SQL 함수는?

    LENGTH 함수는 문자열의 길이(문자 수 또는 바이트 수)를 반환한다. COUNT는 행의 개수를 세는 집계 함수이며 SIZE, WIDTH는 문자열 길이를 구하는 표준 함수가 아니다.

  40. [SQL 기본 및 활용]

    숫자를 지정한 소수점 자리에서 반올림하는 함수로 옳은 것은?

    ROUND 함수는 지정한 자릿수에서 반올림한 값을 반환하는 표준적인 숫자 함수이다. TRUNC는 버림, FIX나 ROUNDUP은 이 문맥의 표준 함수명이 아니다.
